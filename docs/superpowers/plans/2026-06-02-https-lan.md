# HTTPS on the LAN (Caddy + mkcert) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an opt-in HTTPS testing harness — Caddy reverse proxy + mkcert cert — that serves the built PWA at `https://Avi.local` and proxies `/api` + `/socket.io` to Flask, so the service worker registers and the app installs on a phone.

**Architecture:** Pure infra/config: a `Caddyfile`, a PowerShell runner, a guide, and a gitignore entry under `deployment/`. No app code changes. Caddy terminates TLS (mkcert), serves `client/dist/client`, proxies API/socket to `localhost:3000`.

**Tech Stack:** Caddy, mkcert, PowerShell, the existing Angular production build + Flask.

**Verification model:** No unit tests. Task 1 = files committed + `git` clean. Task 2 = host-side TLS check (`https://localhost` serves the PWA with a valid cert + registered SW; `/api` reaches Flask). Admin-only steps (mkcert CA install, 443 firewall rule) are handed to the user.

**Spec:** `docs/superpowers/specs/2026-06-02-https-lan-design.md`
**Branch:** `feature/https-lan` (created; spec committed).

- [ ] **Step 1:** Create `deployment/Caddyfile`:
```
Avi.local, localhost {
	tls deployment/certs/avi.local.pem deployment/certs/avi.local-key.pem

	# API + realtime → Flask (Caddy auto-upgrades WebSockets)
	@backend path /api/* /socket.io/*
	reverse_proxy @backend localhost:3000

	# Built SPA + deep-link fallback
	root * client/dist/client
	try_files {path} /index.html
	file_server
	encode gzip
}
```

- [ ] **Step 2:** Create `deployment/serve-https.ps1`:
```powershell
# Opt-in HTTPS harness for phone/PWA testing. Run from an Administrator
# PowerShell the FIRST time (mkcert -install + firewall need admin).
# Backend must already be running: (cd backend; python main.py)  on :3000.
$ErrorActionPreference = "Stop"
$root = Split-Path $PSScriptRoot -Parent
$certDir = Join-Path $root "deployment\certs"
New-Item -ItemType Directory -Force -Path $certDir | Out-Null
$cert = Join-Path $certDir "avi.local.pem"
$key  = Join-Path $certDir "avi.local-key.pem"

if (-not (Test-Path $cert)) {
  Write-Host "Generating mkcert certificate (first run; needs admin)..."
  mkcert -install
  mkcert -cert-file $cert -key-file $key Avi.local localhost 127.0.0.1
}

Write-Host "Building client (production)..."
Push-Location (Join-Path $root "client"); npm run build; Pop-Location

Write-Host "Serving https://Avi.local  (Ctrl+C to stop)"
Set-Location $root
caddy run --config (Join-Path $root "deployment\Caddyfile")
```

- [ ] **Step 3:** Create `deployment/https-tls.md` (the LAN-HTTPS guide) covering: install (`winget install FiloSottile.mkcert`, `winget install CaddyServer.Caddy`); run backend on :3000; run `serve-https.ps1` from an **admin** PowerShell the first time; firewall rule `New-NetFirewallRule -DisplayName "Rojin HTTPS 443" -Direction Inbound -Protocol TCP -LocalPort 443 -Action Allow -Profile Private`; **phone CA trust** (`mkcert -CAROOT` → `rootCA.pem`; Android: Settings → Security → Install a certificate → CA certificate; iOS: install profile then General → About → Certificate Trust Settings → enable full trust); open `https://Avi.local`; teardown (Ctrl+C, optional disable firewall rule + `mkcert -uninstall`); troubleshooting (port 443 busy → use `Avi.local:8443`; `.local` not resolving → use the LAN IP).
